# 后续需求探索

以下为基于当前使用过程和实现的建议，尚未实现。0.5.0 本次主要更新外观、图标和小窗口下的操作布局，不改变查询、历史、接口和划词行为。

## 建议优先考虑

| 优先级 | 需求 | 当前问题 | 建议的最小版本 |
|---|---|---|---|
| 高 | 检查更新与升级入口 | 朋友合并代码后，用户不易判断本机是否最新，仍需下载解压和调整快捷方式 | 设置页显示本机版本，可主动检查最新 Release，展示更新内容并打开下载页；一键替换程序可作为下一步 |
| 高 | 自动生成发布包 | 代码合并与下载包发布是两个独立步骤，已经出现“源码 0.4.1，下载仍为 0.4.0”的情况 | 在发布版本标签时，通过 GitHub Actions 运行 Windows 构建、测试、生成 ZIP 和 SHA-256，再上传 Release；先不让每次普通提交都发布版本 |
| 中高 | 收藏和单条删除历史 | 历史最多 100 条，重要概念可能被挤出；目前只能清空全部 | 收藏不参与普通历史淘汰，支持逐条删除；沿用本机加密保存，先不做账号与云同步 |
| 中高 | 解释深度与领域选择 | 默认提示词偏计算机，面对其他学科或熟悉的概念时，需要的深度不同 | 提供“快速了解 / 详细解释”以及“自动 / 指定领域”，展示本次采用的选项，继续支持主动提供原句 |
| 中 | 更方便地摘录 | 当前可以复制整份解释，但难以只选一段，整理读书笔记时需要再次编辑 | 支持在卡片中选择复制文字，并提供单条 Markdown 导出；历史批量导出后再考虑 |
| 中 | 窗口位置与置顶开关 | 卡片一直置顶有利于对照阅读，也可能挡住其他应用 | 提供置顶切换与记住尺寸/位置，继续保留“手动关闭才消失”的默认行为 |
| 中低 | 深色模式与对比度 | 长时间夜间阅读时，纯浅色界面可能刺眼 | 先提供浅色/深色两套经过对比度检查的资源，再考虑跟随 Windows 系统设置 |
| 中低 | 快捷键自定义与按应用暂停 | 固定快捷键可能冲突，不同应用的划词体验也不同 | 可自定义查询快捷键，提供应用排除名单；保留现有托盘暂停入口 |

如果只选三项：建议先做“检查更新”，再做“自动发布包”，最后做“收藏和单条删除”。前两项分别解决使用者升级与维护者发布的问题，不能互相替代。

## 设计依据和实现边界

- 参照 [Apple 的布局指南](https://developer.apple.com/design/human-interface-guidelines/layout)组织层次、分组、留白与渐进展示，降低主要操作周围的干扰。
- 参照 [Apple 的材质指南](https://developer.apple.com/design/human-interface-guidelines/materials)区分内容和操作层；当前 WPF 版本通过浅色层次与边框实现，不使用持续模糊、云端图片或额外动画循环。
- 延续 Windows 的窗口操作和本机数据路径，不嵌入 Apple 标志或需要额外授权的 Apple 字体。
- 采用现有矢量标记生成图标，在透明画布中保留安全边距；桌面、托盘、划词入口使用同一套图形。
- 图片 OCR、云同步和自动抓取整页并发送等没有纳入这批建议，继续按现有的文本选区与主动查询范围设计。
